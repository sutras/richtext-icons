# 图标设计语言规范

> 本文件是**图标绘制的唯一权威规范**，人类与 AI 协作时都以它为准。
> 改动图标前先读这里；新增图标时逐条对照，不要凭感觉起稿。

## 1. 总览

- **画布**：`viewBox="0 0 24 24"`，24×24 网格。
- **风格**：线性描边（stroke）为主，少量实心变体（fill）。
- **描边**：`stroke-width="1.5"`（viewBox 用户单位，随尺寸等比缩放）、圆角端点、圆角拐角。
- **颜色**：一律 `currentColor`，禁止写死色值。预览站的颜色调节、深色主题反色都依赖它。
- **尺寸**：组件内宽高写死 `1em`，尺寸由使用处的 `font-size` 决定，无 size prop。

## 2. 源文件是唯一事实来源

- 改图标只改 `icons/<分类>/<名称>.svg`，然后跑 `npm run gen`。
- `src/icons/`、`src/generated/` 均为生成物，**禁止手改**。
- 源文件里必须是真正的 `<path d="…"/>` 等几何元素——生成器把 `<svg>` 的 inner 原样搬进组件，裸路径文本会渲染成空白。
- 用户报「图标不像 / 不显示」时，第一步 diff 源文件与 `src/icons/*.vue` 的 `d`，确认没有「改了源没跑 gen」或「手改生成物」的历史遗留。

## 3. 根节点约定

描边图标根节点：

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24"
     fill="none" stroke="currentColor" stroke-width="1.5"
     stroke-linecap="round" stroke-linejoin="round">
```

- `stroke-width="1.5"` 直接写在源文件，生成器透传，不再由生成器硬编码。
- 颜色只能 `currentColor`；生成器会丢弃 `width`/`height`/`id`/`class`/内联 `style`。
- 实心变体：实心部分用 `fill="currentColor"` 的路径 + `stroke="none"`；源文件里描边元素写在填充元素之前。

## 4. 内容区与布局

- **横向图标**：内容占 `x 4..20` / `y 6..18`。
- **竖向图标**：内容占 `x 6..18` / `y 4..20`（即横向族的 90° 版本）。

## 5. 尺寸红线（20px 下的可读性判据）

这些是踩过坑、用像素级复核定下来的硬规则：

- **实心点半径 ≥ 1.2 单位**。
- **能放字形的容器需 ≥ 14 单位高**（20px 下才放得下字形）。
- **可见净空判据**：`non-scaling-stroke` 下描边在路径两侧各外扩 0.9 用户单位，因此
  **任何两线之间的可见净空 = 路径缺口 − 1.8**。缺口 ≥ 3.8 单位才留得下 2px 可见缝，≥ 3 单位才有 1px。叠层/徽标/缺口的通用判据。
- **禁止用零长路径画点**：`M x y h.01` + 圆头端点的直径恒等于 stroke-width，尺寸放大时点不会变大。
  所有「点」（列表符号、抓手点、`!`/`i`/`?` 的句点、emoji 眼睛）一律用
  `<circle r="1.2" fill="currentColor" stroke="none"/>`——`r=1.2` 是 `list/bullet-list` 定下的全库基准值，不要另造数值。
  排查命令：`grep -n 'h\.01' icons/`（应为空）。

## 6. 家族化造型（跨图标族约定）

### 6.1 表格族（`table/` 20 个）

- 通用表框 = `box(3,3,18,18,r2)` + 2×2 网格线（`x=12`、`y=12`）。
  **2×2 密度是 20px 下的最优解**，3×3 太密。
- 行/列操作 = 表框 **18×10**（2 行，`y 3..13`）/ **10×18**（2 列，`x 3..13`）+ 槽内 **6×6** 徽标
  （行槽 `x 9..15 / y 15..21`，列槽 `x 15..21 / y 9..15`）。徽标**居中于表框的分隔轴**
  （行徽标横向居中 `x=12`，列徽标纵向居中 `y=12`），**外缘对齐 `21`**（行 `y=21`、列 `x=21`）
  ——即徽标吃满 3..21 的内容区，图标整体 bbox 与同族兄弟一致。
- 徽标字形：`+` 插入 / **`×` 删除** / `↑↓←→` 移动，**位置与字形共同指示方向**。
  - **`×` 取 4×4，不能取 6×6**（行 `M14 17 10 21M10 17l4 4`，列 `M17 10 21 14M17 14l4 -4`）。
    同 bbox 的斜角顶点比 `+` 的臂端更靠外：6×6 时顶尖落在 `y=15`，20px 下顶点直接糊在表框底边上
    （可见缝 0.25 单位 ≈ **0.21px**），`×` 读成一坨。缩到 4×4 后可见缝 **2.50 单位 ≈ 2.08px**，
    **与族内移动箭头（`row-move-down`）的缝完全同值**。臂长上 `+` 为 3、`×` 为 2.83，视觉重量相当。
  - **实测改前不对称**：行版 `−`（`M9 18h6`）居中在槽里，可见缝 2.92px；列版 `−`（`M15 12h6`）
    起点顶在槽内侧，可见缝只有 **0.42px**，与表框分不开，形如「分隔线向外拖出」。换 `×` 一并修好。
  - 参考：`+` 的臂端一律贴框（可见缝 0.42px），属既有取舍，未动。
- 实心表达「标头/选中」一律用 `fill="currentColor"` 的路径（随主题自动反色），不要靠加粗描边。
- 颜色类沿用 color 分类的**底部色条**语言（`M4 19.5h16`）。

### 6.2 叠层图标（`media/gallery` = RtiImage 基图 + 右上角横折，表达「多个/图库」）

- 主图形要从 3..21 网格里**主动让出 3 单位**给附属元素，尺寸上限随之降到 **15×15**
  （缺口 2 时净空只剩 0.17px，两线视觉贴死）。
- 附属元素的圆角半径取**与主框 rx 相同**（2.5），直段长度 4–4.5 单位（≤3 读成小钩、≥5 喧宾夺主）。
- 主图形缩小后，内部小元素**不按比例缩**：小圆环内孔 = `2r − 1.8`，太阳保持 `r=1.8`
  （等比缩到 1.55 会在 20px 糊成实心点）。

### 6.3 锁族（`edit/lock` · `edit/unlock`）

- **主语元素逐字节相同**：锁体 `rect(4.5, 10.5, 15, 10.5, r2)` 两图一字不差，锁梁共享前缀
  `M8 10.5V7a4 4 0 0 1 `，拱顶同在 `y=3`。差异只落在「拱尾 + 右腿」。
- **几何约束（决定开口能开多大）**：锁梁 = 半圆拱（腿距 8、`r=4`）+ 两条腿，拱顶钉在 `y=3`。
  半圆拱的自由端必然落在圆心高度 `y=7`，此时开口净空上限 = `(10.5 − 7) − 1.5 = 2.0` 单位
  （1.67px @20px），**刚好卡在第 5 节 2px 判据的下方**。
- **定稿手法：截掉拱尾一小段**（≈10°，自由端落在 `(15.94, 6.31)`——仍在同一圆上，半径误差 0.00004），
  净空提到 **2.69 单位 ≈ 2.24px**，而拱顶与左腿完全不动。**截到 20° 以上（340° / 315° 已实测否决）
  拱就变成「钩子」，读不出锁梁了**。
- 参考：lucide / tabler 的 `lock-open` 同为「锁体不动 + 拆右腿」，但它们把整条锁梁抬高（bbox 随之变化）；
  本库为保成对一致性不抬高，只截拱尾。

## 7. 已占用的语义表达（新图标要避开）

| 表达 | 已占用图标 |
| --- | --- |
| 圆 + 勾 | `success` |
| 方框 + 勾 | `task-list` |
| A + 勾 | `spell-check` |
| 三条带圆点滑杆 | `settings-adjust` |

- **ui/captcha（验证码）**：无通用第三方字形，自定造型 = `rect(3,6,18,12,r2)` + 两行**参差**波浪
  （段宽 3、振幅控制点 1.2，行高 9.3 / 14.7，上行跨 6..18、下行跨 6..15）。
  波浪幅度不能再平（amp 0.9 会读成普通文本行）；两行必须不等长，才读得出「两行验证码字符」。

## 8. 图钉族（`ui/pin` · `ui/pin-filled`）

- 造型沿用 IBM Carbon 的 pushpin，斜置（钉头在右上、针尖在左下）。
- 32 网格 bbox(2..30) 映射到本库 3.2..20.8（scale 0.6286 / offset +1.943），
  坐标烘焙进 24 网格、不用 transform 包裹。
- `pin` = 同一剪影 + 钉身镂空窗（`fill-rule="evenodd"`）；`pin-filled` = 去掉窗的纯实心。
  两者共享剪影，只差一个孔，天然构成「未固定 / 已固定」的 toggle 状态对。
- 镂空环厚约 0.94px（20px），比库里 1.5px 描边略轻，属造型自带、已知取舍。

## 9. 命名与元数据

- **组件名** = 前缀 `Rti` + PascalCase（如 `icons/align/align-left.svg` → `RtiAlignLeft`）。
- **中文名**写在 `icons-meta.json`，key 为 `分类/名称`（不带扩展名），值可简写为字符串，也可展开成
  `{ "zh": "…", "en": "…", "keywords": […], "status": "…" }`。
- **分类清单和组件前缀**在 `icon.config.mjs`。
- **命名撞车警告**：分类名与文件名同名会撞组件名（`insert/table` vs `table/table` 都生成 `RtiTable`），新增图标时注意。

## 10. 新增图标流程

1. 在 `icons/<分类>/<名称>.svg` 建源文件（遵守上文全部规则）。
2. 在 `icons-meta.json` 补中文名 + 英文名 + 中英双语 keywords。
3. 跑 `npm run gen` 生成组件。
4. 用 `svg-icon-candidate-lab` 或预览站做 20px 真实尺寸栅格化复核，确认可读、无贴死/糊点。
5. `npm run typecheck` 通过后再交付。
