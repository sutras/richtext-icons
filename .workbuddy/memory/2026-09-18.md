## 新增纯 ESM 组件库构建脚本 scripts/build-lib.ts

- 需求：把图标打成可发布 npm 的 Vue 组件库，**只 ESM、只 Vue3、带 TS 类型**。参考 cosey/scripts/build.ts 的分步编排。
- 关键决策：**不碰现有 `npm run build`（vite --mode lib）**——那是双格式（es+cjs）+ 预览站雪碧图的流程。新建独立的 `npm run build:lib`，走 Vite JS API + `configFile:false`。

- 类型策略：**不用 vue-tsc 逐组件推导**，而是 manifest 驱动生成 index.d.ts——所有组件统一 `DefineComponent<IconProps & SVGAttributes>`，用一个 `IconComponent` 类型覆盖 151 个，`types.d.ts` 直接复制手写文件。
- 产物：`dist/{index.js,index.d.ts,types.d.ts,package.json,manifest.json,svg/,icon-sprite.svg}`。
- package.json 顶层同步收窄为纯 ESM：删 `require`→cjs 分支，`main`/`module` 都指 index.js，新增 `./types` 子路径导出；vue 移到 peerDependencies（dist/package.json 里）。
- 依赖新增 devDependency `tsx`（跑 .ts 脚本用）。
- 验证：npm pack 后模拟消费者安装，ESM import 151 组件全通、tsc 类型检查（含 `./types` 子路径）零错误。

## subscript / superscript：两个 x 对齐到同一水平线

- 背景：Tiny 报「RtiSubscript RtiSuperscript 两 x 应该在同一水平线」。旧版下标 x 占 y 4.5..12.5、上标 x 占 y 11.5..19.5（各跳 7 单位），单看每个图标重心居中，并排进工具栏却一个上浮一个下沉。
- 判据来源：库内 `font-size-increase/decrease` 这对开关已经是「左 `A` 一字不差，只换右侧 `+ / −`」，sub/sup 应照同一语法。
- 几何推导（关键，避免返工）：设基字中心 `Xc`、半高 `a`、角标高 `h`，要让角标完全位于基字上下之外需同时满足 `Xc − a − h ≥ 3.2` 与 `Xc + a + h ≤ 20.3`——对同一个 `Xc` 无解。**所以角标必须压进基字的纵向区间。**
- 定稿规则：**x 两侧的 path 恒为 `M3.5 8l6 8M9.5 8l-6 8`；下标角标顶边、上标角标底边都落在 y=12（x 的竖中线）**。角标起点 13.5 → **14.6**（下标）/ 5.2 → **6.7**（上标）。**两个字形尺寸一个都没动，只平移**，比缩小角标更省事、也不让小尺寸的 `2` 变虚。

## 新增 edit/unlock（RtiUnlock）—— 与 RtiLock 成对

- 需求：Tiny「已有 RtiLock，新增解锁图标」。库内先做同概念邻座检查：`ui/password` 是钥匙（圆环+杆+齿），不撞脸；`edit/lock` 在 edit 分类，故新图标放 `icons/edit/unlock.svg`（无 `unlink` 先例，命名不冲突）。

- 定稿几何（关键）：
  - 锁体 `rect(4.5, 10.5, 15, 10.5, r2)` 与 lock **逐字节相同**；锁梁共享前缀 `M8 10.5V7a4 4 0 0 1 `，拱顶同在 y=3。
  - lock 锁梁 `M8 10.5V7a4 4 0 0 1 8 0v3.5`；unlock `M8 10.5V7a4 4 0 0 1 7.94 -0.69`（截拱尾 ≈10°）。
  - 由来：半圆拱（腿距 8、r=4）拱顶钉在 y=3 时，自由端**必然**落在圆心高度 y=7，开口净空上限 = (10.5−7)−1.5 = **2.0 单位（1.67px @20px）**，卡在库内 2px 判据下方；截掉拱尾 10° 后净空 **2.69 单位 ≈ 2.24px**。
  - 端点取 `(15.94, 6.31)`：仍在同一圆上（3.94²+0.69² = 15.9997 → r = 3.99996，误差 0.00004），且只有 2 位小数、比按角度算的 4 位小数可读。
  - 实测否决：截 20°（340°）起拱就变成「钩子」，读不出锁梁；抬高锁梁 1 单位虽开口更大，但破坏成对 bbox。
- 候选实验：7 套几何 × 96/48/20px（20px 用 rsvg-convert + Pillow NEAREST ×18/×22/×24 复核），并有「紧邻并排 + 过锁体顶边 y=10.5 的红线」专图判读开口。
- 质量断言（96px 逐行/逐列比对 lock vs unlock）：拱顶同一着墨行、锁体底边同一行、锁体左右边界逐像素一致；着墨差异只出现在锁梁右侧。
- 元数据 `icons-meta.json`：`"edit/unlock": { zh 解锁, en Unlock, keywords [unlocked, lock open, 解锁], tags [权限, 锁定] }`（tags 与 lock 相同，便于按标签成组检索）。

## 行/列删除徽标 `−` → `×`（RtiRowDelete / RtiColumnDelete）

- 需求：Tiny「把短横线改为 x，这样删除意味更强」。
- 定案几何（各行只改徽标那一行，表框与分隔线逐字节未动）：
  - `row-delete`：`<path d="M9 18h6"/>` → `<path d="M14 17 10 21M10 17l4 4"/>`
  - `column-delete`：`<path d="M15 12h6"/>` → `<path d="M17 10 21 14M17 14l4 -4"/>`
  - 规则：**`×` 取 4×4，外缘对齐 y=21 / x=21（吃满 3..21 内容区），居中于表框分隔轴**（行 x=12、列 y=12）。
- **为什么不能沿用 `+` 的 6×6 bbox**：`+` 是轴对齐字形，臂端在边中；`×` 是斜角字形，顶点即 bbox 四角。6×6 的 `×` 顶尖落在 y=15，与 `+` 同位置——但 `+` 的臂端顶到表框读作「贴附」（0.42px 缝，既有取舍），`×` 的两条斜臂同时顶框就读成一坨。实测：6×6 → 0.21px 缝、5.6×5.6 → 0.42px、5×5 → 0.62px、4.4×4.4 → 0.83px，全糊；**只有缩到 4×4 才有 2.08px 缝**。
- 量化方法：rsvg-convert 渲染 96px → PIL 扫描 ink 分组（阈值 <200）→ 量「表框底边墨迹末行」到「徽标首行」的间隔。家族既有基准：`+` 0.42px / 箭头 2.08px / 旧 `−` 行版 2.92px。**`×` 的 2.08px 与箭头完全同值**，落在家族既有区间内。
- 顺带发现并修好：旧列版 `−`（`M15 12h6`）起点顶在槽内侧，可见缝只有 **0.42px**，与表框分不开，形如「分隔线向外拖出」——行版 `−` 居中在槽里（2.92px），两版本来不对称。
- 判读手段：**20×20 真实像素 ASCII 亮度图**（rsvg 出 20px → 逐像素打字符梯度）+ NEAREST ×22 放大图 + 家族整排并排 + 全表族 20 个 @20px 栅格。做过的淘汰项：6×6 / 5.6 / 5.0 / 4.6 / 4.24 / 4.4 居中 / 4.4 上移 0.2；`×4.24` 与 `×4.4` 在 20px 下与 4.0 几乎无差，但缝更小。
- 文档：`docs/icon-design.md` §6.1 重写——徽标字形改 `×`、补 `×` 的尺寸红线与「不能同 bbox」的原因；**并修正该节两处与实际不符的尺寸**（原文「表框 18×12 / 12×18、槽内 5×5」，实际为 **18×10 / 10×18、槽 6×6**）。
- 复验：浅色（96/48/20px + 家族并排 + 全表族）+ **深色主题用「透明底 rsvg 渲染 + PIL 合成到 #1a1b1e」**（rsvg 不支持任意底色）；20px 真实尺寸下 `×` 的斜角顶点抗锯齿后仍清晰。typecheck 通过；build:lib 82.63 kB（+0.03 kB）；预览站 5276 实测「删除当前行 / 删除当前列」与 `+`、箭头同排判读清楚。
