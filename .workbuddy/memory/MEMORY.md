# richtext-icons 项目约定

## 项目定位
富文本编辑器 SVG 图标库。Vite 8（Rolldown）+ Vue 3，Node ≥22.12，用 managed node 22.22.2 路径执行 npm/node。
当前规模：**155 个图标 / 14 个分类**，统一线性描边（24×24、圆角端点、currentColor）。
实心变体（caret/pin-filled/close-filled 等）：实心部分用 `fill="currentColor"` 路径 + `stroke="none"`，源文件里描边元素写在填充元素之前。

## 组件 API 约定（2026-09 定稿）
- **图标组件没有任何 prop**：宽高恒定 `1em`（尺寸跟随使用处 font-size）、描边恒定 `1.5`（**viewBox 用户单位，随 1em 等比缩放**），均由生成器写死进组件。
  `vector-effect="non-scaling-stroke"` 已于 2026-09-18 移除（省约 17KB），`1.5` 不再是「屏幕像素」。→ 尺寸红线里所有按「屏幕像素」推算的数值都要按这一条复核。
- 组件是**纯 template 文件**（无 `<script>` 块）；`IconProps` 接口已删除，`IconComponent = DefineComponent<SVGAttributes>`。
- 用户通过 CSS 控制图标：`style="font-size: 20px; color: #2f6feb"`；class/style/事件透传到 `<svg>` 根节点（默认 inheritAttrs 行为）。
- 无障碍语义（role/aria-hidden/title）已被移除——Tiny 明确决策，勿在 review 时「修复」加回来。

## 核心约定
- **SVG 源文件是唯一事实来源**：改图标只改 `icons/<分类>/<名称>.svg`，然后 `npm run gen`；`src/icons/`、`src/generated/` 均为生成物，禁止手改。
- **源文件与生成物可能脱节**：生成器把 `<svg>` 的 inner 原样搬进组件，所以源文件里必须是真正的 `<path d="…"/>`（裸路径文本会渲染成空白）。用户报「图标不像 / 不显示」时，第一步先 diff 源文件与 `src/icons/*.vue` 的 `d`，确认没有「改了源没跑 gen」或「手改生成物」的历史遗留。
- 图标规格：viewBox 24×24；描边风格 `fill="none" stroke="currentColor"` 圆角端点；`stroke-width="1.5"` **由源文件根节点显式声明、生成器原样透传**（无硬编码、无配置项，源文件是唯一事实来源）；颜色禁止写死，统一 currentColor（预览站颜色调节依赖）。
- 中文名写在 `icons-meta.json`（值可直接用字符串简写；key 为 `分类/名称` 不带扩展名）；分类清单和组件前缀在 `icon.config.mjs`。
- 组件名 = 前缀 `Rti` + PascalCase（如 `icons/align/align-left.svg` → `RtiAlignLeft`）。
- 库入口 `src/generated/index.ts` 导出所有组件 + `iconList`/`ICON_NAMES`/`ICON_COUNT`。

## 常用命令
- `npm run dev`（生成 + 预览站，端口 5273）
- `npm run gen`（唯一生成命令，已无 svgo/gen:opt）
- `npm run build:lib`（发布用，纯 ESM 组件库 → dist/，见「发布定位」）
- `npm run typecheck`（vue-tsc）

## 发布定位（重要）
- **只面向「通过 Vue 组件使用」的用户**，不导出原始 SVG / 雪碧图 / manifest.json。
- 发布包 = `dist/index.js` + `index.d.ts` + `types.d.ts` + `metadata.js` + `metadata.d.ts`；`dist/package.json` 已不再产出（package.json 的 exports 直接指向 dist/）。exports 三个子路径：`.`、`./metadata`、`./types`。
- 构建产物大小（2026-09-18）：index.js 82.09 kB / gzip 12.06 kB；metadata.js 54.96 kB / gzip 9.36 kB。**metadata 必须生成时直接序列化轻量字段**——用运行时 `map` 剥离 `svg` 不会被 tree-shake。
- 雪碧图、原始 SVG 导出、`symbolId` 字段已彻底移除（2026-09-18 瘦身）。

## 预览站调试备注
页面是**单页滚动式文档站**（Hero → 文档 → 图标画廊），body 正常滚动，不再是旧版单屏 `.scroll` 容器。
- 顶栏 sticky；搜索输入关键词会自动 `scrollIntoView('#icons')`；`.gallery { scroll-margin-top: calc(var(--header-h) - 1px) }`。
- 需并排大量图标做复核时：`agent-browser eval` 摘出每个 `svg.outerHTML` + `getComputedStyle(svg).color`，重建一张本地复验页再截图（一次拿到所有尺寸 × 主题）。
- 画廊卡片结构：**图标在卡片顶部、中文名 + 组件名在图标下方**（卡片 div 的 `textContent` 为空，取标签要向上找约 5 层祖先）。`scrollTo` 后立刻截图会有 ~30px 漂移 → 截完先回读 `window.scrollY` 再按 `getBoundingClientRect` 裁切，或一次截「两张卡片同框」的宽幅带。

## 设计语言（跨图标族约定）
- **内容区**：横向图标占 x 4..20 / y 6..18；竖向图标占 x 6..18 / y 4..20（即横向族的 90° 版本）。
- **家族化造型**：list 三图标 + line-height =「左标记 + 右三横」；align 六图标 =「三条平行线」或「参考线 + 线条元素」。
- **标题族 H1–H6（2026-09-19 补齐 h4/h5/h6）**：左侧 `H`（`M3.5 5.5v13M10.5 5.5v13M3.5 12h7`）六图逐字节相同；右侧数字 1..6，顶统一 y=7.5、底 18..18.5、x ≈14.5..21，数字最左元素与 H 右竖（x=10.5）缺口 ≥3.9 单位（20px 下 2px 净空）。
  - `4` = 竖线 `M19 7.5v11` + 斜线横线一笔 `M19 7.5l-4.3 6.5h6`；**横线必须向右出头**（到 x=20.7，过竖线 1.7 单位）——Tiny 明确反馈过「4 那一横要出头」。
  - `5` = 顶横+左竖一笔（`M20.5 7.5h-5V12`）+ 碗（中横过渡→右弧→底 y=18→左上收笔）；碗底必须到 18，浅碗在 20px 糊成一团。
  - `6` = **长弧 + 四段 90° C 整环，弧终点落在环 135° 点 (15.45,13.05) 且终止切向 = 环切向 (−0.707,+0.707)**（无缝衔接）；环心 (17.5,15.1) r=2.9、k·r=1.6。教训：**只让端点落在环上、切线不连续会被读成 C**（Tiny 反馈「上面弧度和下面圆连接不连贯」）；弧太短接在环右上则读成 d——长弧必须从右上扫到环左上。
- **开关对（toggle pair）铁律：主语字形逐字节相同，只挪修饰元素。** 库内两对：
  - `font-size-increase` / `font-size-decrease`：左侧 `A` 的 `M3.2 19 7.5 7.5 11.8 19M4.8 15.5h5.4` 一字不差，只换右侧 `+ / −`。
  - `format/subscript` / `format/superscript`（2026-09-18 修正）：`x` 恒为 `M3.5 8l6 8M9.5 8l-6 8`（占 y 8..16、x 3.5..9.5），角标 `2` 字形尺寸不动，只平移——**下标角标顶边 / 上标角标底边都正好落在 x 的竖中线 y=12 上**（起点 14.6 / 6.7）。
  - 旧版让 x 上下各跳 7 单位（下标 x 在上半、上标 x 在下半），单看重心居中，**放进工具栏却一个上浮一个下沉**——Tiny 报的正是这个。**推论：修饰元素必须与主语字形纵向区间重叠，不能整体让开**；「基字固定 + 修饰元素完全位于其上下之外」在 24 网格里数学上无解。逐图标重心居中是错的优化目标，成对一致性才是。
- **表格族**（table 分类 20 个）：
  - 通用表框 = 24 网格内 `box(3,3,18,18,r2)` + 2×2 网格线（x=12、y=12）；**2×2 密度是 20px 下的最优解**，3×3 太密。
  - 行/列操作 = 表框 **18×10**（2 行，y 3..13）/ **10×18**（2 列，x 3..13）+ 槽内 **6×6** 徽标（行槽 x 9..15/y 15..21，列槽 x 15..21/y 9..15）；徽标居中于表框**分隔轴**（行 x=12、列 y=12），**外缘对齐 21**，吃满 3..21 内容区。
  - 徽标字形：`+` 插入 / **`×` 删除** / `↑↓←→` 移动，**位置与字形共同指示方向**。
  - **`×` 只能取 4×4**（行 `M14 17 10 21M10 17l4 4`；列 `M17 10 21 14M17 14l4 -4`）。同 bbox 6×6 的 `×` 顶尖落在 y=15，20px 下**糊在表框上**（可见缝 0.21px）；4×4 时可见缝 2.50u = **2.08px，与移动箭头同缝**。`×` 是斜角字形，顶点即 bbox 四角，与轴对齐的 `+` 不能同 bbox 类比。
  - **可见缝家族基准**（96px 栅格 + 阈值 <200 量 ink 分组）：`+` 0.42px（贴框，既有取舍）/ 箭头 2.08px / 旧 `−` 行版 2.92px、**列版仅 0.42px（改前的隐藏不对称，已随 `×` 一并修好）**。
  - 实心表达「标头/选中」一律用 `fill="currentColor"` 的路径（随主题自动反色），不要靠加粗描边。
  - 颜色类沿用 color 分类的**底部色条**语言（`M4 19.5h16`）。
- **叠层图标**（`media/gallery` = RtiImage 基图 + 右上角横折，表达「多个/图库」）：
  - 主图形要从 3..21 网格里**主动让出 3 单位**给附属元素，尺寸上限随之降到 **15×15**（缺口 2 时净空只剩 0.17px，两线视觉贴死）。
  - 附属元素的圆角半径取**与主框 rx 相同**（2.5），直段长度 4–4.5 单位（≤3 读成小钩、≥5 喧宾夺主）。
  - 主图形缩小后，内部小元素**不按比例缩**：小圆环内孔 = 2r − 1.8，太阳保持 r=1.8（等比缩到 1.55 会在 20px 糊成实心点）。
- **尺寸红线**：实心点半径 ≥1.2 单位；20px 下能放字形的容器需 ≥14 单位高；描边（`stroke-width="1.5"` 用户单位）在路径两侧各外扩 **0.75** 用户单位 → **任何两线之间的可见净空 = 路径缺口 − 1.5 单位**；20px 下 1 单位 ≈ 0.833px，故缺口 ≥3.9 单位才留得下 2px 可见缝、≥2.7 单位才有 1px（叠层/徽标/缺口的通用判据）。**注**：该组数值原按 `non-scaling-stroke`（外扩 0.9 / 净空 −1.8）推导，描边语义变更后已按用户单位重算；`docs/icon-design.md` 里仍是旧数字，尚未同步。
- **禁止用零长路径画点**：`M x y h.01` + 圆头端点的直径恒等于 stroke-width（1.5 单位），比 `r=1.2` 的实心圆（直径 2.4 单位）细得多，读起来像一粒灰。所有"点"（列表符号、抓手点、`!`/`i`/`?` 的句点、emoji 眼睛）一律用 `<circle r="1.2" fill="currentColor" stroke="none"/>`——`r=1.2` 是 `list/bullet-list` 定下的全库基准值，不要另造数值。
  排查命令：`grep -n 'h\.01' icons/`（应为空）。源文件里描边元素写在填充元素之前。
- **命名**：分类名与文件名同名会撞组件名（`insert/table` vs `table/table` 都生成 `RtiTable`），新增图标时注意。
- **ui/captcha（验证码）**：无通用第三方字形，自定造型 = `rect(3,6,18,12,r2)` + 两行**参差**波浪（段宽 3、振幅控制点 1.2，行高 9.3 / 14.7，上行跨 6..18、下行跨 6..15）。波浪幅度不能再平（amp 0.9 会读成普通文本行）；两行必须不等长，才读得出"两行验证码字符"。**该族已被占用的表达**：圆+勾（success）、方框+勾（task-list）、A+勾（spell-check）、三条带圆点滑杆（settings-adjust）——验证码类新图标都要避开。
- **图钉族（ui/pin · ui/pin-filled）**：造型沿用 IBM Carbon 的 pushpin，斜置（钉头在右上、针尖在左下）。32 网格 bbox(2..30) 映射到本库 3.2..20.8（scale 0.6286 / offset +1.943），坐标烘焙进 24 网格、不用 transform 包裹。`pin` = 同一剪影 + 钉身镂空窗（`fill-rule="evenodd"`），`pin-filled` = 去掉窗的纯实心；两者共享剪影，只差一个孔，天然构成「未固定 / 已固定」的 toggle 状态对。镂空环厚约 0.94px（20px），比库里 1.5px 描边略轻，属造型自带、已知取舍。
- **锁族（edit/lock · edit/unlock，2026-09-18）**：锁体 `rect(4.5,10.5,15,10.5,r2)` 两图**逐字节相同**，锁梁共享前缀 `M8 10.5V7a4 4 0 0 1 `、拱顶同在 `y=3`；差异只落在「拱尾 + 右腿」。`lock` = `…8 0v3.5`（右腿落到锁体），`unlock` = `…7.94 -0.69`（截掉拱尾 ≈10°，自由端 `(15.94, 6.31)`，仍在同一圆上）。
  几何约束：半圆拱（腿距 8、r=4）拱顶钉在 y=3 时，自由端必然落在圆心高度 `y=7`，**开口净空上限只有 2.0 单位（1.67px @20px），卡在 2px 判据下方** → 想达标只能截拱尾；**截到 20° 以上就变「钩子」**（340°/315° 已实测否决）。成对一致性优先于「把锁梁抬高」（lucide/tabler 的 lock-open 抬高锁梁，bbox 随之变化，本库不采用）。
- **侧栏开关族（view/side-panel-open · side-panel-close）**：骨架两图**逐字节相同** = 表框 `rect(3,4,18,16,r2)` + 分隔线 `M15 4v16`（侧栏 = 右侧 15..21 那条窄带）。差异只有「杆 + 箭头」两条 path：`open` = `M6.5 12h5` + `M9 9.5l2.5 2.5L9 14.5`（**箭头指向侧栏 = 向右**），`close` = `M11.5 12h-5` + `M9 9.5L6.5 12 9 14.5`（**背离侧栏 = 向左**），箭头活动区恒为 x 6.5..11.5。
  2026-09-18 Tiny 判定原版语义反了，已把两文件内容**整体对调**（框架/分隔线逐像素未动，只换箭头；git blob 直接互换）。**注意这与 lucide 的 `panel-right-open/close` 方向相反**（lucide：open 箭头背离面板）——库内以本条为准，勿再按 lucide 翻回去。

## 分类与元数据维护
- **【强制】每次图标数量变化（新增/删除/重命名）后，必须同步更新文档里的计数，一处都不能漏**。具体位置：
  1. `README.md` 有**两处**计数——「分类规划」概述段的总数（`全部 14 个分类已建成，共 **N 个图标**`）+ 下方分类表的每分类数量与代表图标；两处都要改（2026-09-19 曾漏掉概述段那处，只剩分类表改对）。
  2. `AGENTS.md` 规模行（`规模：N 个图标 / 14 个分类…`）。
  3. 本项目 `MEMORY.md`「项目定位」行的规模数。
  4. **预览站**：`src/components/SiteHero.vue` 的 hero 徽标已改为 `stats.total` / `stats.categories` **动态取数，无需手改**（2026-09-19）；`index.html` 的 `<meta name="description">` 里硬编码了「N 个图标、14 个分类」，**要手改**（`dist-site/index.html` 是构建产物，随 `build:site` 自动更新，勿手改）。
  - 以 `npm run gen` 输出的「图标 N 个 · 分类 M 个」为准，别手数。
- `docs/icon-gaps.md` 是**带日期的审计快照**（写死 106 个），不要当实时数据改。
